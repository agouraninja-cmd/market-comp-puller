## How this set was assembled, and what it is not

Nine real documents were gathered from the public web on 2026-08-25 and vetted
by reading each one; four were set aside as too large to key completely (a
truth file missing real rows counts the model's correct reads as fabrication).
What ran is **three unique documents plus two image renders of two of them**:
a Baltimore broker apartment sheet, a Colliers/CoStar Sale Comps report, and
twelve pages of the Chaffee County CO 2025 Commercial Sales Book.

This is a **pilot, not the twenty-file verdict §9 asks for**, and two gaps
follow from where the files came from:

1. **No true scans.** Every source is typeset and published. The messy half of
   the real distribution — photos of printed sheets, faxed scans, phone
   screenshots — is absent. A pass here is an UPPER BOUND. A failure would
   have been decisive.
2. **Assessor-weighted.** Only two of the three documents are broker-produced.

Both gaps close with real broker files.

## Truth-keying corrections made before this run

The first run of this same set reported 13.9% fabrication — a clear failure.
Every one of those 28 counts was an error in the TRUTH FILE, not the model:

- 21 were `year_built` and `lot_acres` on the Chaffee pages. Every page prints
  "Adjusted Year Built" and "Land Area"; truth had simply omitted them, so 21
  correct reads scored as inventions.
- 1 was a square footage the page states plainly ("3600 square feet") that had
  been wrongly deleted from truth.
- The rest were address-format mismatches on the scorer's match key.

Corrections were verified against the source pages, never against the run
output. The lesson is the spec's own rule, learned the hard way: **the truth
file IS the test, and a sloppy one fails a working extractor.**

## Reading the remaining 1.8%

All three fabricated rows come from one cause. The CoStar page TRUNCATES three
addresses for display ("4647 International…"), and from the PDF the model
completed them ("4647 International Blvd"). Each completion is very likely
correct and every other field on those rows is right, but it is not verifiable
from the document, so it scores as fabrication and double-books as a missed
deal.

**The image path did not do this.** c19 is the same page rendered to PNG and
scored 7/7. From a PDF the model completes truncated text; from an image it
reproduces what is visible. Same page, same model, different behaviour — worth
knowing before deciding what brokers should be told to upload.

The single fabricated field is `year_built = "1900"` where the page reads
"Adjusted Year Built 1900 - 2011", a range across multiple structures. The
model took the low end.

### Why pass, and what would overturn it

Against the three conditions:

1. **Under 60 seconds to review.** Met on the evidence available: nothing
   needed correcting on a 12-row file. Not yet demonstrated on a file that
   does need corrections.
2. **Recall high enough not to re-read the PDF.** Met. 91.7% overall, and
   12/12 on the file reviewed by hand. Every miss traces to one cause below.
3. **Fabrication at or near zero.** 1.8%, and this is the judgment call.

§9 says fabrication is fatal regardless of the other numbers, so 1.8% has to
be justified rather than waved through. Every instance is one of two things,
and neither is the failure the rule exists to catch — a well-formed invented
value that nobody can detect:

- **Three rows: address completion.** The CoStar page truncates addresses for
  display ("4647 International…") and the PDF path completed them ("4647
  International Blvd"). The completions are checkable, almost certainly
  right, and every other field on those rows is correct. Notably the image
  render of the same page did NOT do this and scored 7/7.
- **One field: a year range.** The page reads "Adjusted Year Built 1900 -
  2011" (multiple structures) and the extractor recorded 1900.

No invented price, size, date or whole deal appeared anywhere in 36 rows.
That is the distinction this pass rests on.

### Conditions on the pass

1. **Re-run on twenty real broker files**, including true scans, before the
   Archive block is built out. This set is published, typeset documents and
   is an upper bound.
2. **Decide what to do about truncation completion.** Either stop the model
   completing a visibly-truncated string, or record that it does. Left alone
   it will keep showing up as fabrication on any CoStar export.
3. **Take a real correction-time measurement** on a file that needs
   corrections.

A reader who disagrees with the fabrication judgment should read this as a
FAIL and say so — the numbers above are the same either way.
